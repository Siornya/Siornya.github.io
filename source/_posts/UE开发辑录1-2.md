## 时间系统的模型

游戏时间系统大致有以下几种结构：

1. 基于真实时间
   游戏内时间基于真实时间
   比如游戏时间直接等同于显示是时间，或者按照一定规则缩放现实时间，比如现实时间十分钟对应游戏内一小时
   这种时间系统可以用于计算离线收益
2. Tick时刻
   最经典的游戏逻辑时间，创建一种时间单位称为`Tick`游戏刻
   并且将其与实际时间联系起来，例如每秒刻数`TPS`，每刻毫秒数`MSPT`
   每次更新时计算距离上次更新经过的时间`DeltaTime`，并换算出经过的刻数`DealtaTime/TPS`
   这种时间系统具有完全确定性，保存存档和联机同步都很方便
3. 离散时间
   这种时间系统中只有时间段，没有连续流动的具体时间
   比如早晨，上午，中午，夜晚，第几回合或者第几天
   通过某些事件来使时间进入下一阶段
   这种时间系统大多用于Galgame，桌游等游戏

在本文中，我们主要讨论使用Tick驱动的游戏时间系统

## 子系统设计

时刻子系统的核心职责很简单：**把UE的帧更新（`DeltaTime`）转换为确定性的游戏刻**。

它需要做三件事：

1. 累积真实时间，到达一个游戏刻的时长时触发一次游戏刻
2. 维护一个全局游戏刻计数器 `TotalTicks`
3. 通过委托通知其他系统"现在到了第X刻"

对于TPS（每秒刻数），一个合理的默认值是20，即每刻50ms。这与Minecraft的游戏刻一致，也足够大多数策略/模拟类游戏使用。

> **关于确定性**：游戏刻的确定性来自于它基于计数而非浮点时间。两个客户端只要收到相同的输入序列，在相同的刻数上执行，结果就完全一致。

## 实现

### 创建子系统类

时刻子系统继承自 `UGameInstanceSubsystem`，生命周期与游戏实例相同，跨关卡持久存在。同时实现 `FTickableGameObject` 接口来接入UE的Tick管线。

**`TickSubsystem.h`**

```cpp
#pragma once

#include "CoreMinimal.h"
#include "Subsystems/GameInstanceSubsystem.h"
#include "Tickable.h"
#include "TickSubsystem.generated.h"

DECLARE_MULTICAST_DELEGATE_OneParam(FOnGameTick, int64 /*CurrentTick*/);

UCLASS()
class YOURGAME_API UTickSubsystem : public UGameInstanceSubsystem, public FTickableGameObject
{
    GENERATED_BODY()

public:
    // ---------- UGameInstanceSubsystem ----------
    virtual void Initialize(FSubsystemCollectionBase& Collection) override;
    virtual void Deinitialize() override;

    // ---------- FTickableGameObject ----------
    virtual void Tick(float DeltaTime) override;
    virtual TStatId GetStatId() const override;
    virtual bool IsTickable() const override { return !IsTemplate(); }

    // ---------- 游戏刻接口 ----------

    // 订阅游戏刻事件
    FOnGameTick OnGameTick;

    UFUNCTION(BlueprintPure, Category = "Tick")
    int64 GetCurrentTick() const { return TotalTicks; }

    // 将刻数换算为现实秒数
    UFUNCTION(BlueprintPure, Category = "Tick")
    float TicksToSeconds(int64 Ticks) const;

    // 将现实秒数换算为刻数（向下取整）
    UFUNCTION(BlueprintPure, Category = "Tick")
    int64 SecondsToTicks(float Seconds) const;

    // 从存档数据恢复刻计数（由存档系统调用）
    void LoadTicks(int64 SavedTicks);

public:
    // 每秒游戏刻数，建议保持为常量，修改会破坏已有存档的时间换算
    static constexpr float TicksPerSecond = 20.f;

private:
    UPROPERTY()
    int64 TotalTicks = 0;

    float AccumulatedTime = 0.f;
};
```

### Tick逻辑

**`TickSubsystem.cpp`**

```cpp
#include "TickSubsystem.h"

void UTickSubsystem::Initialize(FSubsystemCollectionBase& Collection)
{
    Super::Initialize(Collection);
    AccumulatedTime = 0.f;
}

void UTickSubsystem::Deinitialize()
{
    Super::Deinitialize();
}

void UTickSubsystem::Tick(float DeltaTime)
{
    constexpr float SecondsPerTick = 1.f / TicksPerSecond;

    AccumulatedTime += DeltaTime;

    // 一次帧更新可能跨越多个游戏刻（比如帧率低于TPS时）
    while (AccumulatedTime >= SecondsPerTick)
    {
        AccumulatedTime -= SecondsPerTick;
        TotalTicks++;
        OnGameTick.Broadcast(TotalTicks);
    }
}

TStatId UTickSubsystem::GetStatId() const
{
    RETURN_QUICK_DECLARE_CYCLE_STAT(UTickSubsystem, STATGROUP_Tickables);
}

float UTickSubsystem::TicksToSeconds(int64 Ticks) const
{
    return static_cast<float>(Ticks) / TicksPerSecond;
}

int64 UTickSubsystem::SecondsToTicks(float Seconds) const
{
    return static_cast<int64>(Seconds * TicksPerSecond);
}

void UTickSubsystem::LoadTicks(int64 SavedTicks)
{
    TotalTicks = SavedTicks;
    AccumulatedTime = 0.f;
}
```

`while` 循环而非 `if` 是关键细节：当游戏卡顿导致单帧 `DeltaTime` 很大时，所有积压的游戏刻会在当帧依次触发，保证了逻辑的完整性。

### 订阅游戏刻事件

其他子系统或Actor订阅 `OnGameTick`，在委托回调中执行需要按刻驱动的逻辑：

```cpp
// 在某个子系统或组件的 Initialize / BeginPlay 中
UTickSubsystem* TickSys = GetGameInstance()->GetSubsystem<UTickSubsystem>();
if (TickSys)
{
    TickSys->OnGameTick.AddUObject(this, &UMySystem::HandleGameTick);
}

// 回调
void UMySystem::HandleGameTick(int64 CurrentTick)
{
    // 每刻执行一次，CurrentTick 就是当前刻数
    // 可以用 CurrentTick % N == 0 来实现"每N刻执行一次"的节流
    if (CurrentTick % 20 == 0) // 每20刻（1秒）执行一次
    {
        ProcessPerSecondLogic();
    }
}
```

记得在 `Deinitialize` 或 `EndPlay` 时移除订阅，防止野指针：

```cpp
TickSys->OnGameTick.RemoveAll(this);
```

## 存档支持

游戏刻计数器是存档中最关键的字段之一，所有基于时间的状态（比如建筑剩余建造刻数）都依赖它。

在你的存档结构体中添加：

```cpp
USTRUCT()
struct FGameSaveData
{
    GENERATED_BODY()

    UPROPERTY(SaveGame)
    int64 TotalTicks = 0;

    // ... 其他存档字段
};
```

存档时：

```cpp
SaveData.TotalTicks = TickSubsystem->GetCurrentTick();
```

读档时：

```cpp
TickSubsystem->LoadTicks(SaveData.TotalTicks);
```

`LoadTicks` 同时重置了 `AccumulatedTime`，避免加载后立即触发额外的游戏刻。

## 使用示例：建造队列

以建筑建造为例，展示时刻子系统的实际使用方式。建造任务只需存储"完成时刻"，不需要存储倒计时：

```cpp
USTRUCT()
struct FBuildTask
{
    GENERATED_BODY()

    UPROPERTY(SaveGame)
    FName BuildingId;

    // 存储绝对刻数，而非剩余时间
    UPROPERTY(SaveGame)
    int64 CompletionTick = 0;
};
```

添加任务时：

```cpp
void UBuildingSystem::EnqueueBuild(FName BuildingId, float DurationSeconds)
{
    UTickSubsystem* TickSys = GetGameInstance()->GetSubsystem<UTickSubsystem>();

    FBuildTask Task;
    Task.BuildingId = BuildingId;
    Task.CompletionTick = TickSys->GetCurrentTick() + TickSys->SecondsToTicks(DurationSeconds);
    BuildQueue.Add(Task);
}
```

在游戏刻回调中检查完成：

```cpp
void UBuildingSystem::HandleGameTick(int64 CurrentTick)
{
    for (int32 i = BuildQueue.Num() - 1; i >= 0; i--)
    {
        if (BuildQueue[i].CompletionTick <= CurrentTick)
        {
            CompleteBuild(BuildQueue[i].BuildingId);
            BuildQueue.RemoveAt(i);
        }
    }
}
```

计算进度和剩余时间：

```cpp
float UBuildingSystem::GetBuildProgress(const FBuildTask& Task, int64 StartTick) const
{
    UTickSubsystem* TickSys = GetGameInstance()->GetSubsystem<UTickSubsystem>();
    int64 Current = TickSys->GetCurrentTick();
    float Progress = static_cast<float>(Current - StartTick) / (Task.CompletionTick - StartTick);
    return FMath::Clamp(Progress, 0.f, 1.f);
}

float UBuildingSystem::GetRemainingSeconds(const FBuildTask& Task) const
{
    UTickSubsystem* TickSys = GetGameInstance()->GetSubsystem<UTickSubsystem>();
    int64 Remaining = Task.CompletionTick - TickSys->GetCurrentTick();
    return TickSys->TicksToSeconds(FMath::Max(0LL, Remaining));
}
```

这种设计的优势在于**存档不会因为离线时间而产生问题**。读取存档时，`CompletionTick` 是一个固定值，与加载时刻做比较即可判断是否已完成，不需要任何特殊的"离线计算"逻辑。
